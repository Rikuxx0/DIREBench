# 実装失敗と除外記録

`20261126T193950Z-S1-independent-B0-7028d608` は侵害 Pod 自身を隔離した後、同 Pod 内の Secret プローブがタイムアウトした。Frontend/Worker の処理成功は観測できたが、機密性側の実測が欠けるため全体のリスク判定を `null` とした。正常トラフィックの成功だけで安全試行と再分類しない。

`20261126T200331Z-S4-parallel-B3-9c2ce929` は初期版 B3 の試行であり、実測リスクが発生した。両操作とも `REOBSERVE` の後に `ALLOW` され、先に承認した隔離の予約が再観測後の状態から失われていた。`supervisor_decisions.jsonl` と `ground_truth.json` を原証拠として保存する。

原因は並行バッチ内の再観測時に、実クラスタの現在状態だけで再判断し、実行前に承認済みの操作を投影しなかったこと。修正版では再観測した状態に予約済み操作を投影してから、次の操作を予測する。修正版の独立試行 `20261126T200454Z-S4-parallel-B3-ee04505f` は A を許可し B を拒否、実測リスクなしだった。

両試行の測定値は変更しない。初期版を修正版 B3 の集計から除外し、失敗事例として報告する。試行実行中にソースを編集したため、両者の `source_sha256` が同じ値になった。今後は一つの実験バッチ中にソースを変更せず、プロセス開始時のソース・ハッシュと各試行開始時のハッシュを併記する。この一連の比較は探索的結果として扱い、正式な B3 性能推定には再現バッチを要する。

初期の状態採取では `kubectl get ... -o json` の一覧 metadata にある `resourceVersion` が空で、B3 の S5 再観測は主に経過時間の閾値で起動した。各リソースの `metadata.resourceVersion` を保存するよう修正し、実クラスタで非空の版を確認した。以前の S5 試行の測定値は保持するが、版不整合の検出を実証したとは扱わない。版修正後の S5 再試行を別途保存する。

`20261126T204809Z-S4-parallel-B3-242dde59` は `evidence=false` で実行したが、初期版 Runner が証拠ファイルを出力した。判断結果そのものは保存するが、証拠生成オフのアブレーションとしては無効である。証拠と説明ファイルを出力しないよう修正して再試行する。元のファイルは削除しない。
