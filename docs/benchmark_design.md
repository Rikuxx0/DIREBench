# ベンチマーク設計

最初に B0 の固定操作で現象を測定し、次に予測モデルを較正する。評価用シナリオは因果構造ごとに分離する。危険ラベルは仮説としてのみ保存し、正解は実際の操作前後・無操作対照の差から判定する。

状態には資産、ID、実効権限、通信可能性、AND/OR 型サービス依存、稼働状態、侵害主体、制約、権限リース、操作履歴、観測時刻、版を含める。構成由来のグラフ辺とプローブで実測した辺は `source` を分ける。対象の NetworkPolicy が実際に強制されないクラスタでは S1/S4/S5 の結果を無効にする。

比較条件: B0 は環境境界のみ、B1 は認可と対象だけ、B2 は単一操作後の予測状態、B3 は系列・並行性・鮮度を扱う。B2+系列、B2+鮮度、B2+両者、さらに証拠生成のアブレーションを独立に記録する。証拠生成自体は判断を変えない。全拒否を負の対照に含める。

開発用と最終評価用の因果テンプレートを分ける。現 MVP の各カテゴリ一組は探索的試行であり、汎化性能の推定には使用しない。
